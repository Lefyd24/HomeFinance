# .impeccable.md

## Design Context

### Users
Single-user personal finance app (self-hosted). The user is both the owner and the only real
audience — a technically fluent individual reviewing their own transactions, budgets, debts and
recurring expenses, usually on a laptop at home, sometimes on mobile. Not a multi-tenant SaaS
product, so no need to design for a generic "persona" — design for a careful, numbers-literate
user who wants clarity over decoration.

### Brand Personality
Derived from the existing app (the light/dark token sets in
`frontend/app/src/index.css`):
- **Calm, precise, unshowy.** Teal-blue primary (`oklch(52% .105 223)` light / `oklch(60% .126
  221)` dark), neutral base surfaces, restrained 1px borders via `color-mix(... base-content
  N%, transparent)` rather than heavy shadows.
- **Ledger-literate.** Tabular numerals (`.fin-numeric`), thin rule dividers, small-caps uppercase
  section labels with wide tracking, soft category-tinted accents (`--cat-1..6`).
- **Quietly crafted, not flashy.** Only one existing use of `backdrop-filter` in the whole app
  (`.report-filter-card`), used sparingly for a sticky filter bar — glass is an accent, not a
  default surface treatment.

### Aesthetic Direction
- Theme: both light (`light-fin`) and dark (`dark-fin`), following the existing `data-theme`
  toggle — never hardcode one theme.
- Font: Poppins (already loaded app-wide via Google Fonts link in every page `<head>`) — do not
  introduce a second font family for AI features; consistency with the rest of the app matters
  more than novelty here.
- Anti-reference: generic AI-chatbot UI (centered rounded bubbles on a plain white scroll,
  purple/blue gradient accents, glowing borders). This is a finance tool, not a consumer chat app.
- Glassmorphism is requested specifically for the floating chat input bar/composer (both the
  popup widget and the dedicated full-page chat) — apply it there deliberately, not to every
  surface.

### Design Principles
1. Extend the existing `fin-*` design language (fin-card, fin-chip, fin-status, fin-surface,
   fin-track) instead of inventing a parallel visual system — the AI feature should look like it
   shipped with the app, not bolted on.
2. Reserve glass/blur for the one place it was asked for: the floating input bar. Transcript
   surfaces stay solid, matching `dash-panel`/`fin-card` treatment.
3. Respect `prefers-reduced-motion`; reuse the existing `fin-panel-in` stagger/easing curves
   already defined in custom.css rather than inventing new motion timing.
4. Tool-call activity (the "what is it doing" live indicator) should read as an audit trail —
   small pill entries with a status dot, echoing `.fin-status`/`.fin-chip`, not a generic spinner.
